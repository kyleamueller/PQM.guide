## Remarks

`Type.Facets` returns a record describing the **facets** of a type: optional annotations that describe a type in more detail than its base kind, such as a text column's maximum length or a decimal column's precision. The record always has the same nine fields: `NumericPrecisionBase`, `NumericPrecision`, `NumericScale`, `DateTimePrecision`, `MaxLength`, `IsVariableLength`, `NativeTypeName`, `NativeDefaultExpression`, and `NativeExpression`. These match the facet columns that `Table.Schema` reports.

For types written as literals (like `type number` or `type text`), every field is `null`, meaning no facet has been set. Facets become meaningful on types that come from data sources. For example, a SQL Server `nvarchar(50)` column's type can carry `MaxLength = 50`, `IsVariableLength = true`, and `NativeTypeName = "nvarchar"`.

Facets are informational only: M does not enforce them when values are created or converted.

`Type.Facets` is used in advanced introspection scenarios: custom connectors, schema comparison tools, or type annotation pipelines. The output of `Type.Facets` is a standard record that you can inspect with record field access or convert to a table with `Record.ToTable`. The complement function `Type.ReplaceFacets` creates a new type with modified facets.

Note that `Type.Facets` operates on a **type value**, not a data value. Use `Value.Type(x)` to obtain the type of a data value before passing it to `Type.Facets`.

## Examples

### Example 1: Facets of a plain number type — all null

A type written as a literal carries no facets, so every field in the record is null.

```powerquery
Type.Facets(type number)
```

{"columns":[{"name":"Name","type":"text"},{"name":"Value","type":"any"}],"rows":[{"Name":"NumericPrecisionBase","Value":null},{"Name":"NumericPrecision","Value":null},{"Name":"NumericScale","Value":null},{"Name":"DateTimePrecision","Value":null},{"Name":"MaxLength","Value":null},{"Name":"IsVariableLength","Value":null},{"Name":"NativeTypeName","Value":null},{"Name":"NativeDefaultExpression","Value":null},{"Name":"NativeExpression","Value":null}]}

### Example 2: Facets of a nullable text type

Nullability isn't a facet, so `type nullable text` also returns a record of nulls.

```powerquery
Type.Facets(type nullable text)
```

<!--output
{"columns":[{"name":"Name","type":"text"},{"name":"Value","type":"any"}],"rows":[{"Name":"NumericPrecisionBase","Value":null},{"Name":"NumericPrecision","Value":null},{"Name":"NumericScale","Value":null},{"Name":"DateTimePrecision","Value":null},{"Name":"MaxLength","Value":null},{"Name":"IsVariableLength","Value":null},{"Name":"NativeTypeName","Value":null},{"Name":"NativeDefaultExpression","Value":null},{"Name":"NativeExpression","Value":null}]}
-->

### Example 3: Facets after applying precision and scale with Type.ReplaceFacets

Attach `NumericPrecision` and `NumericScale` facets (like a SQL `DECIMAL(10, 2)` column), then read them back.

```powerquery
let
    Constrained = Type.ReplaceFacets(type number, [NumericPrecision = 10, NumericScale = 2])
in
    Type.Facets(Constrained)
```
